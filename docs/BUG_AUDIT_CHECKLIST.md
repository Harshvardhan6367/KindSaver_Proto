# KindReport Jaipur — Bug Audit Checklist

This checklist tracks every finding identified, reproduced, remediated, and verified during the comprehensive bug audit.

| Finding ID | Severity | Description | Status | Verification Evidence |
| :--- | :--- | :--- | :--- | :--- |
| **AUDIT-001** | **P0 - Critical** | Client-side stored auth session is never validated against server on app mount, leaving invalid/expired sessions active until failed interaction | **VERIFIED** | Verified via `App.jsx` `validateSession()` calling `/api/auth/me` on mount + `onAuthChange` event listener in `api.js` |
| **AUDIT-002** | **P1 - High** | Duplicate civic report merging fails to record reporter user ID, causing citizen's report to vanish from "My Reports" dashboard | **VERIFIED** | Verified via `backend/regression.test.js` (Test 4: Merged duplicate report retains reporterUserId and appears in `/api/citizen/my-reports`) |
| **AUDIT-003** | **P1 - High** | Uploaded photo evidence URL omitted from incident schema and public API responses, leaving photos missing on Map and Track screens | **VERIFIED** | Verified via `backend/regression.test.js` (Test 5: Photo evidence persisted on incident and returned in `/api/incidents` and `/api/incidents/ticket/:id/details`) |
| **AUDIT-004** | **P1 - High** | MapScreen crashes with white blank screen if dashboard statistics are loading or null due to unsafe property traversal on `stats?.totals` | **VERIFIED** | Verified via optional chaining (`stats?.totals?.reports ?? 0`) and Vite production bundle compilation |
| **AUDIT-005** | **P2 - Medium** | Malformed JSON request bodies cause HTTP 500 Internal Server Error instead of HTTP 400 Bad Request | **VERIFIED** | Verified via `backend/regression.test.js` (Test 1: Malformed JSON payload returns HTTP 400 with syntax error message) |
| **AUDIT-006** | **P2 - Medium** | Missing payload size limits in HTTP body reader exposes server to memory exhaustion / heap DoS via oversized streams | **VERIFIED** | Verified via `backend/regression.test.js` (Test 2: Stream > 10MB rejected with HTTP 413 Payload Too Large) |
| **AUDIT-007** | **P2 - Medium** | Memory leak in in-memory rate limiter where IP address entries are never pruned over time | **VERIFIED** | Verified via pruning logic in `checkRateLimit` removing expired entries when table exceeds 1,000 keys |
| **AUDIT-008** | **P2 - Medium** | Media service throws unhandled 500 error when requested file does not exist on disk | **VERIFIED** | Verified via `backend/regression.test.js` (Test 6: Missing media returns clean 404 response) |
| **AUDIT-009** | **P2 - Medium** | Geographic coordinates out of WGS84 bounds (-90 to 90, -180 to 180) bypass input validation and crash backend domain layer | **VERIFIED** | Verified via `backend/regression.test.js` (Test 3: Coordinate validation rejects out-of-range latitude/longitude with 400) |
| **AUDIT-010** | **P2 - Medium** | Token verification in `verifyToken` throws unhandled SyntaxError on malformed base64 JSON payloads | **VERIFIED** | Verified via `backend/regression.test.js` (Test 7: Tampered base64 payload returns null safely) |
| **AUDIT-011** | **P2 - Medium** | Citizen dashboard profile save does not synchronize with active `App.jsx` user state | **VERIFIED** | Verified via `onUpdateUser` prop in `CitizenDashboard.jsx` synchronizing with `App.jsx` React state |
| **AUDIT-012** | **P2 - Medium** | `TrackScreen` search input fails to synchronize when user navigates using "Track Ticket" buttons across pages | **VERIFIED** | Verified via `useEffect` sync hook on `ticketId` prop in `TrackScreen.jsx` |
| **AUDIT-013** | **P2 - Medium** | `PhotoUpload` accepts unsupported image types and leaks blob object URLs in browser memory | **VERIFIED** | Verified via `ALLOWED_MIME_TYPES` strict set and `URL.revokeObjectURL` cleanup |
| **AUDIT-014** | **P2 - Medium** | Topbar navigation and portal mode toggle overflows horizontally on mobile viewports (<768px and <480px) | **VERIFIED** | Verified via media query rules for `.topbar-center-nav`, `.portal-mode-pill-toggle`, `.tabs`, and Vite build output |
| **AUDIT-015** | **P3 - Low** | Topbar brand element lacks keyboard accessibility handler (`onKeyDown`) | **VERIFIED** | Verified via `onKeyDown` supporting Enter and Space key activation |
| **AUDIT-016** | **P1 - High** | Private resident contact data leaked on public ticket details endpoint (`reporterPhone`, `reporterUserId`, and `reporterName` exposed without authentication) | **VERIFIED** | Verified via `backend/regression.test.js` (Test 8: Public incident details sanitizes reporter contact info via `toPublicIncident`) |
| **AUDIT-017** | **P1 - High** | Unrestricted duplicate and post-resolution community confirmations (infinite report boosting, confirmations allowed on closed tickets) | **VERIFIED** | Verified via `backend/regression.test.js` (Test 11: Rejects duplicate confirmations from same device with 409 Conflict; rejects confirmations on resolved/closed tickets with 400) |
| **AUDIT-018** | **P2 - Medium** | Malformed URI component encoding crashes HTTP router with uncaught 500 URIError | **VERIFIED** | Verified via `backend/regression.test.js` (Test 9: `safeDecodeURIComponent` in `server.js` returns HTTP 400 Bad Request) |
| **AUDIT-019** | **P2 - Medium** | Reopening resolved/closed incidents preserves old `resolvedAt` and `closedAt` timestamps, corrupting SLA and audit metrics | **VERIFIED** | Verified via `backend/regression.test.js` (Test 12: Transition to reopened/in_progress resets `resolvedAt` and `closedAt` to null) |
| **AUDIT-020** | **P2 - Medium** | N+1 sequential scanning query loop in `listCitizenReports` and missing MongoDB collection indexes for `reporterUserId` | **VERIFIED** | Verified via store-level `listReportsByReporterUserId` implementations in both `memoryStore` and `mongoStore`, plus MongoDB indexes in `mongoCollections.js` |
| **AUDIT-021** | **P2 - Medium** | Official municipal admin credentials mismatch (`admin@jaipur.gov.in` referenced in UI placeholders but absent in memory seed) | **VERIFIED** | Verified via `backend/regression.test.js` (Test 15: Both `admin@jaipur.gov.in` and `admin@kindreport.local` authenticate successfully) |
| **AUDIT-022** | **P2 - Medium** | Profile updates silently ignored invalid names/wards, and `assignIncident` accepted arbitrary invalid priority values | **VERIFIED** | Verified via `backend/regression.test.js` (Tests 13 & 14: Strict 400 validation for priority and profile data) |
| **AUDIT-023** | **P2 - Medium** | Over 50 unstyled CSS classes across Citizen Portal, Track Screen, and Auth Modal causing mobile layout collapse and unstyled tables | **VERIFIED** | Verified via responsive CSS additions in `styles.css` and verified via Vite production build (`npm run frontend:build`) |
| **AUDIT-024** | **P2 - Medium** | Report form state retained previous submission photos and coordinates after filing | **VERIFIED** | Verified via `App.jsx` resetting `reportForm` to `DEFAULT_REPORT_FORM` upon submission success |
| **AUDIT-025** | **P2 - Medium** | Admin operations status modal lacked `reopened` option, preventing staff from reopening closed tickets | **VERIFIED** | Verified via `AdminScreen.jsx` status options update and regression testing |
| **AUDIT-026** | **P1 - High** | Swallowed API exception in `App.jsx` `confirmIncident` causing client UI (`TrackScreen.jsx`) to display green success banner even when server rejected with 409 Conflict (duplicate) or 400 (closed ticket) | **VERIFIED** | Verified via error re-throw in `App.jsx` `confirmIncident` and frontend build verification |
| **AUDIT-027** | **P1 - High** | Password reset (`/api/auth/reset-password`) failed to invalidate previously active JWT tokens, allowing hijacked tokens to remain usable for 12 hours | **VERIFIED** | Verified via `backend/regression.test.js` (Test 17: Password reset immediately revokes all pre-existing session tokens with millisecond-precision cutoff) |
| **AUDIT-028** | **P1 - High** | Media upload endpoint (`/api/media/upload`) checked only string `Content-Type` header without inspecting binary magic bytes, allowing non-image files to masquerade as images | **VERIFIED** | Verified via `backend/regression.test.js` (Test 16: Binary magic byte verification rejects fake image upload with HTTP 400) |
| **AUDIT-029** | **P2 - Medium** | Incident mutation endpoints (`/confirm`, `/status`, `/assign`) failed when passed human-readable Ticket IDs (`KR-2026-XXXX`) instead of UUIDs, and lacked URI parameter decoding | **VERIFIED** | Verified via `backend/regression.test.js` (Test 18: Confirmation, status updates, and officer assignment accept Ticket ID format seamlessly) |
| **AUDIT-030** | **P2 - Medium** | MongoDB `users` collection lacked an index on `{ id: 1 }`, causing full collection scans O(N) on every token authentication and `getUserById` lookup | **VERIFIED** | Verified via index creation in `backend/store/mongoCollections.js` with `{ id: 1 }, { unique: true }` |
| **AUDIT-031** | **P2 - Medium** | Authenticated resident reports dropped reporter phone numbers because `signToken` omitted `phone` and `wardNumber` from the JWT claims payload | **VERIFIED** | Verified via `backend/regression.test.js` (Test 21: Citizen reports retain `reporterPhone` from registration profile) |
| **AUDIT-032** | **P2 - Medium** | Priority calculation produced `NaN` age in hours when incident records missed `createdAt`, silently poisoning score math and defaulting urgent issues to "low" priority | **VERIFIED** | Verified via `backend/regression.test.js` (Test 19: Priority calculation defensively handles missing or corrupt `createdAt` without `NaN`) |
| **AUDIT-033** | **P2 - Medium** | Rate limiter unconditionally trusted `X-Forwarded-For` header regardless of proxy configuration, enabling trivial rate limit evasion via client IP spoofing | **VERIFIED** | Verified via `backend/regression.test.js` (Test 20: `trustProxy` setting in `config.js` and header check in `server.js`) |
| **AUDIT-034** | **P2 - Medium** | `pointInPolygon` crashed with unhandled TypeError if any ward boundary record had null, undefined, or empty coordinate arrays | **VERIFIED** | Verified via `backend/regression.test.js` (Test 22: `detectWard` defensively handles null or malformed polygon structures) |
| **AUDIT-035** | **P3 - Low** | CSS issue badge class names in `styles.css` (`type-garbage`, `type-drain_blockage`) mismatched domain enum values (`type-garbage_dump`, `type-drain_blocked`), rendering badges without distinct styling | **VERIFIED** | Verified via updated badge styles in `frontend/src/styles.css` matching all domain `ISSUE_TYPES` |
| **AUDIT-036** | **P3 - Low** | "Registered Citizens" management tab in Admin Screen was visible to `ward_officer` role, but clicking it caused an unhandled 403 Forbidden error | **VERIFIED** | Verified via RBAC guard in `AdminScreen.jsx` restricting the tab to `currentUser?.role === 'admin'` |
